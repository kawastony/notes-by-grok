# Timing recognition protocol

Tony Kawas / 13 September 2026.  
Analogy: daytime keys that unlock a dream — not forced symbols.

Goal: give the framework a **way to recognize timing**, using only what is already derived.  
Not a new epoch. Not clock = map change. Not slip turn-on.

---

## 1. What “timing” is allowed to mean

| Allowed | Forbidden (rescue) |
|---|---|
| When the **mechanism activates** (pause / freeze / late-time residual) | When the **metric class (M1)** flips |
| When the **activation map** \(\beta(y)=g(z)\) crosses the critical surface | When \(\eta\) turns on |
| Structural window from \(\Delta y\) + O(1) drivers | \(z=12\), dictionary Jacobian as a date |

The only derived timing object is the **activation interval**.

## 3. What counts as a daytime “ping”

A ping is an external or structural fact that **unlocks** the clock without stretch — same rule as a dream key: recognition, not invention.

### Valid pings (recognition)

1. **Geometric ping**  
   The 5D system returns a stable \(\Delta y\) of the derived size; the map to \(z\) with O(1) drivers lands late-time.  
   → *Already happened.* Clock is recognized internally.

2. **Overlap ping**  
   An independent construction in the lineage (e.g. Paper 3 transition \(z_{\mathrm{tr}}\approx 0.35\)) falls inside the same window **without** retuning \(\Delta y\).  
   → Mutual recognition, not proof they are identical objects.

3. **Falsification ping (negative recognition)**  
   If a claimed activation for *this* interval were required at \(z\gtrsim 1\) or \(z\sim 12\), the day **rejects** the claim.  
   → Recognizing “not this clock.”

### Invalid pings (forced symbols)

- Equating \(z_{\mathrm{act}}\) with an M1 map transition  
- Reading \(11/72\) or \(R\approx 1.5156\) as a date  
- Reading slip onset as the meaning of the clock  
- Stretching drivers (\(\gamma\) far from O(1)) only to hit a preferred redshift  

Those are invented meanings, not recognition.
